# HabitHero 孩子冒險板與家長任務行事曆實作規格

**狀態：** Ready for implementation  
**日期：** 2026-07-31  
**範圍：** 孩子角色首頁左側冒險卡、每日／一般冒險完成流程、家長任務排程與行事曆  
**產品原則：** 孩子看到的是冒險；家長操作的是任務與排程。  

---

## 1. 本規格的產品決策

本次改造以角色首頁為主要操作畫面，不再要求孩子先開啟「今日目標」功能頁才能看到任務。

確定採用：

- 角色首頁左側顯示兩張冒險卡：
  - `每日冒險`
  - 可由家長改名的 `一般冒險`
- 兩張卡進入首頁時一律為收合狀態。
- 兩張卡使用完全相同的展開、收合與淡入淡出行為。
- 點擊卡片標題才展開任務清單。
- 任務列只顯示：
  - 完成狀態
  - 任務標題
- 不在任務列顯示點數、分類、時間、建立者或說明。
- 點擊任務列後開啟任務詳情，所有執行與完成操作在詳情內完成。
- 孩子送出完成後，角色首頁左側立即打勾並更新進度。
- 若任務需要家長審核，打勾代表「孩子已完成並送出」，不代表點數已經發放。
- 每日冒險不要求完成心得。
- 一般冒險至少需要簡單回報；家長可以進一步要求完整文字心得。
- 移除「再完成一個冒險，房間就會有變化！」及其他未實作房間變化的承諾文案。
- 家長端新增：
  - 每日冒險排程
  - 一般冒險管理
  - 月／週行事曆
  - 當日孩子任務狀態

本次不做：

- 房間隨完成數變化。
- 裝備、道具或房間解鎖。
- 隨機寶箱、抽卡或多種貨幣。
- 照片與語音證明。
- 孩子之間的排行榜。
- 拖曳改期。

## 2. 名詞與資料語意

### 2.1 冒險類型

```text
daily   = 每日冒險
general = 一般冒險
```

每日冒險：

- 由家長建立排程。
- 可設定每週哪些日子出現。
- 每一個排程日都要產生獨立的任務實例。
- 當天的完成紀錄不能在隔日被覆寫或重設。
- 孩子不能自行把任務標記為每日冒險。

一般冒險：

- 可由家長建立。
- 也可由孩子提出，經家長確認後加入。
- 不會在跨日後自動重設。
- 保留在目前的一般冒險集合中，直到完成或由家長封存。
- 一般冒險卡標題可由家長修改，例如：
  - 星球挑戰
  - 這週任務
  - 暑假冒險
  - 家庭英雄任務

### 2.2 完成狀態

孩子首頁使用以下視覺語意：

```text
☐ 尚未完成，可以執行
◷ 尚未到時間、等待家長確認或暫時不可執行
☑ 孩子已送出完成或已經核准
!  家長要求補充
```

任務列仍只顯示圖示與標題。詳細原因只在點擊任務後顯示，避免左側清單資訊過多。

### 2.3 進度數字

```text
每日冒險 1/5
一般冒險 1/3
```

分子：

- `pending`
- `completed`

以上兩種都算孩子已經送出完成，所以左側立即計入進度。

以下狀態不計入分子：

- `proposed`
- `proposal_revision_requested`
- `todo`
- `revision_requested`

分母：

- 當張冒險卡目前顯示的所有有效任務。
- 不包含已取消、已封存或不屬於今天的每日任務。

家長退回補充時：

- 任務從 `pending` 變成 `revision_requested`。
- 左側勾選改為 `!`。
- 進度分子減一。
- 不扣除既有點數，因為此時尚未發點。

## 3. 孩子首頁文字線框

### 3.1 預設收合

```text
┌──────────────────────┬────────────────────────────────────┐
│                      │                                    │
│  小宇的冒險           │                                    │
│                      │             角色房間場景             │
│  ┌────────────────┐  │                                    │
│  │ 每日冒險   1/5 〉│  │                                    │
│  └────────────────┘  │                                    │
│                      │                                    │
│  ┌────────────────┐  │                                    │
│  │ 星球挑戰   1/3 〉│  │                                    │
│  └────────────────┘  │                                    │
│                      │                                    │
│                      │                         背包／設定   │
└──────────────────────┴────────────────────────────────────┘
```

不得顯示：

```text
再完成一個冒險，房間就會有變化！
```

### 3.2 展開每日冒險

一次只允許展開一張冒險卡。展開每日冒險時，若一般冒險已開啟，應先開始收合一般冒險，再展開每日冒險。

```text
┌────────────────────┐
│ 每日冒險       1/5 ﹀│
├────────────────────┤
│ ☑ 刷牙              │
│ ☐ 看英文            │
│ ☐ 打籃球            │
│ ☐ 整理書包          │
│ ☐ 收好玩具          │
└────────────────────┘

┌────────────────────┐
│ 星球挑戰       1/3 〉│
└────────────────────┘
```

### 3.3 展開一般冒險

```text
┌────────────────────┐
│ 每日冒險       1/5 〉│
└────────────────────┘

┌────────────────────┐
│ 星球挑戰       1/3 ﹀│
├────────────────────┤
│ ☑ 完成英文作業       │
│ ☐ 幫忙整理客廳       │
│ ☐ 畫一張全家福       │
└────────────────────┘
```

### 3.4 空狀態

收合時仍顯示 `0/0`：

```text
每日冒險 0/0
星球挑戰 0/0
```

展開後：

```text
今天沒有每日冒險
```

```text
目前沒有一般冒險
```

孩子自行新增一般冒險的入口放在一般冒險展開內容最下方：

```text
＋ 我想新增冒險
```

入口不放在每日冒險內，避免孩子利用每日冒險跳過回報規則。

## 4. 冒險卡互動與動畫規格

### 4.1 初始狀態

- 每次進入或重新掛載角色首頁，兩張卡都收合。
- 展開狀態只存在目前畫面生命週期，不寫入資料庫或 `localStorage`。
- 即時資料更新不得自動展開卡片。
- 任務完成後回到首頁時：
  - 保留原本展開的卡片。
  - 更新該列勾選與進度。

### 4.2 點擊規則

- 點擊卡片標題列：
  - 收合 → 展開
  - 展開 → 收合
- 點擊任務列：
  - 不改變冒險卡收合狀態。
  - 開啟任務詳情。
- 點擊完成任務列：
  - 開啟唯讀詳情。
  - 不允許再次提交。
- 卡片標題列與任務列實際觸控區域不得小於 `44px`。
- 鍵盤可使用 `Enter` 或 `Space` 展開／收合。
- 卡片標題需提供 `aria-expanded` 與清楚的可及性名稱。

### 4.3 淡入淡出

兩張卡必須共用同一動畫元件與同一組 timing token，不得各自實作。

展開：

```text
內容 opacity 0 → 1
內容 translateY -4px → 0
時間 220ms
easing ease-out
```

收合：

```text
內容 opacity 1 → 0
內容 translateY 0 → -4px
時間 180ms
easing ease-in
```

規則：

- 收合時內容必須等淡出完成後才卸載，避免瞬間消失。
- 展開內容整體淡入，不對每一列使用長時間 stagger。
- 箭頭旋轉可與內容同步，但不得造成標題列位移。
- 不得使用會讓鄰近元素跳動的 margin 動畫。
- 不得使用 `display: none` 直接跳過離場動畫。
- 快速連點時，動畫必須可反向或以最新狀態為準，不可卡在半透明狀態。
- 切換到另一張卡時，不得同時存在兩個可點擊的重疊內容區。
- `prefers-reduced-motion: reduce`：
  - 不執行位移。
  - 以接近即時的狀態切換完成。
  - 功能與焦點順序保持一致。

CSS owner：

- 冒險板的角色首頁幾何位置與 responsive：`src/styles/character.css`
- 冒險板表面色、文字色、邊框與主題色：`src/styles/neutral-theme.css`
- 若任務詳情使用 overlay：`src/styles/overlays.css`
- 禁止在其他檔案末端追加覆蓋式 CSS。

## 5. 任務詳情與完成流程

### 5.1 每日冒險詳情

```text
┌──────────────────────────────────┐
│ ← 返回                           │
│                                  │
│             刷牙                 │
│                                  │
│ 爸媽寫的任務說明                  │
│                                  │
│ 時間與點數等資料                  │
│                                  │
│        [ ✓ 我完成了 ]             │
└──────────────────────────────────┘
```

每日冒險：

- 不顯示心得欄位。
- 不要求心情或難度。
- 如果有必要計時，必須先完成計時條件。
- 按下完成後立即關閉詳情並在左側顯示勾選。
- 若需要家長審核，狀態進入 `pending`。
- 若任務有點數，點數只有在家長核准後發放。

### 5.2 一般冒險詳情

一般冒險至少要完成簡單回報，不可完全略過。

預設簡單回報：

```text
這次冒險怎麼樣？

[ 很順利 ] [ 有點難 ] [ 我需要幫忙 ]

                     [送出完成]
```

家長設定為完整心得時：

```text
這次冒險怎麼樣？

[ 很開心 ] [ 很有成就 ] [ 有點累 ] [ 有點挫折 ]

我想告訴爸媽：
┌────────────────────────────┐
│ 必填文字心得                 │
└────────────────────────────┘

                     [送出完成]
```

規則：

- 孩子自行提出的任務一律屬於一般冒險。
- 孩子不能把自行提出的任務改成每日冒險。
- 一般冒險的回報模式最少為 `quick`，不能設定為 `none`。
- 完整心得模式必須驗證去除空白後的文字。
- 簡單回報必須選擇一個結構化選項。

## 6. 完成判定：什麼才算達成

### 6.1 產品上的「達成」

App 能驗證的是孩子是否完成數位流程，不能證明現實世界中真的刷牙或打球。

因此：

- `☑` 表示孩子已自行確認並完成系統要求的提交。
- 若家長要求審核，最終發點仍由家長決定。
- 不宣稱 App 可以自動驗證現實行為。

### 6.2 後端必須驗證的完成條件

孩子送出完成時，後端必須一次驗證：

1. 使用者是該孩子帳號，或是正在操作該家庭孩子視角的合法家長。
2. 任務屬於目前家庭與目前孩子。
3. 任務狀態允許提交：
   - `todo`
   - `revision_requested`
4. `proposed` 與 `proposal_revision_requested` 不得提交完成。
5. 任務目前日期有效。
6. 任務目前時間位於可執行區間。
7. 沒有其他啟用 `requires_review_before_next_task` 的阻擋任務。
8. 若任務需要計時，伺服器記錄的有效累積時間已達要求。
9. 每日冒險不接受心得欄位作為必要條件。
10. 一般冒險已滿足回報模式：
    - `quick`：必須有合法選項。
    - `reflection`：必須有非空白文字、合法心情與難度。
11. 同一個提交請求只能成功一次。
12. 狀態更新、提交內容與事件紀錄必須在同一個 transaction 完成。

只要任一條不成立：

- 後端拒絕狀態變更。
- 前端撤回 optimistic 勾選。
- 顯示可理解的原因。
- 不得寫入點數。

### 6.3 計時不能跳過

現有計時器主要存在 React state 與 `localStorage`，只能提供 UX，不能作為不可跳過的完成證據。

若某任務設定「必須完成計時」：

- 開始、暫停、繼續與累積時間必須保存到伺服器。
- 不採信裝置傳入的「我已計時完成」布林值。
- 不採信使用者修改後的裝置時間。
- 同一孩子同時只能有一個 running timer。
- 卡片收合、切換功能頁、App 進入背景都不代表自動完成。
- 倒數到零只解鎖「我完成了」，不直接提交完成。
- 暫停後只能累積實際完成的時間。
- 重新登入或換裝置後必須能讀取相同的 timer session。

若本輪不新增伺服器 timer session：

- 計時只能標示為「輔助計時」。
- 不得宣稱不能跳過。
- 完成按鈕不得把本地 timer 當成安全驗證。

## 7. 防止跳過與重複發點

### 7.1 不可只靠前端隱藏

以下限制必須由 RPC／資料庫再驗證，不能只靠 disabled button：

- 孩子不能把一般冒險改成每日冒險。
- 孩子不能把回報模式改成 `none`。
- 孩子不能自己改點數。
- 孩子不能直接把狀態改為 `completed`。
- 孩子不能跳過 `proposed` 的家長確認。
- 孩子不能在時間區間外提交。
- 孩子不能重複提交同一個任務。
- 家長不能重複核准並重複發點。

### 7.2 點數規則

- 孩子送出完成時不發點。
- 左側可以立即打勾，但點數維持不變。
- 家長核准時：
  - 任務變成 `completed`。
  - point ledger 寫入一筆唯一的 `task_approved`。
  - 孩子點數在同一 transaction 增加。
- 同一 `task_id` 最多只能有一筆 `task_approved` ledger。
- RPC 重試或雙擊核准不得產生第二筆點數。
- 零點任務仍可完成，但不寫入零點 ledger。

### 7.3 快速連點

孩子按下「我完成了」後：

- 立即鎖定提交按鈕。
- 使用穩定的 idempotency key。
- 同一任務的第二個請求需回傳第一次結果，不重複處理。
- optimistic UI 可以立即打勾。
- 失敗時回復原狀並顯示原因。

## 8. 每日冒險不能直接重設同一筆任務

現有 `is_daily` 布林值不足以安全支援每日完成歷史。

禁止採用：

```text
每天午夜把昨天同一筆 completed 任務改回 todo
```

這會造成：

- 昨天完成紀錄消失。
- `completed_at` 被覆寫。
- 成長統計失真。
- point ledger 與 task 狀態不一致。
- 家長行事曆無法顯示過去日期。
- 跨裝置同步容易把舊狀態覆蓋回來。

正確模型：

```text
每日排程 task_schedule
        ↓
每天產生獨立 task occurrence
        ↓
當日完成、審核與點數都綁定 occurrence
```

### 8.1 建議資料結構

`task_schedules`：

```text
id
family_id
child_profile_id
name
description
points
category
duration_minutes
start_time
end_time
weekdays
timezone
requires_timer
requires_review_before_next_task
active_from
active_until
is_active
created_at
updated_at
```

`tasks` 增加：

```text
adventure_type              daily | general
schedule_id                 nullable
occurrence_date             Asia/Taipei date
completion_report_mode      none | quick | reflection
```

唯一約束：

```text
unique(schedule_id, child_profile_id, occurrence_date)
```

用來防止：

- App 重開重複產生任務。
- 多台裝置同時載入重複產生任務。
- 排程 worker 重試造成重複任務。

### 8.2 產生日任務

- 以 `Asia/Taipei` 判斷日期與星期。
- 可由後端排程預先產生，或在讀取當日資料時使用 idempotent RPC 補產生。
- 前端不得自行建立每日 occurrence 並視為唯一真相。
- 午夜跨日時重新讀取新的 occurrence。
- 昨天尚未完成的每日任務不帶到今天的每日卡。
- 昨天資料仍保留在行事曆與歷史紀錄。

## 9. 一般冒險集合與改名

每個孩子同時間只有一個「目前的一般冒險集合」。

建議資料：

`adventure_groups`：

```text
id
family_id
child_profile_id
type                       general
title
status                     active | archived
created_at
archived_at
```

規則：

- 每個孩子最多一個 active general group。
- 預設名稱為「一般冒險」。
- 只有家長可以修改 group title。
- 標題去除前後空白後必須為 1–12 個中文字元或等值長度。
- 不允許空白、純符號或與「每日冒險」完全相同。
- 改名不影響任務歷史或狀態。
- 孩子新增的一般冒險在家長確認後加入 active group。
- 已完成任務保留在目前 group，直到家長封存該 group。
- 封存時：
  - 已完成任務保留在歷史。
  - 尚未完成任務必須先移至新 group、取消或明確保留；不可靜默遺失。
- 建立新 group 後進度從新的任務集合重新計算。

## 10. 孩子自建任務與既有流程衝突

孩子自行新增：

```text
建立一般冒險
    ↓
proposed
    ↓
家長確認名稱、點數、分類、時間與回報模式
    ↓
todo
    ↓
孩子才可送出完成
```

規則：

- `proposed` 可以顯示在一般冒險卡，但圖示為 `◷`。
- 點擊後顯示「等待家長確認」。
- 不顯示可用的完成按鈕。
- 家長確認前不得啟動強制計時。
- 家長退回提案時顯示補充入口。
- 孩子不能藉由先完成再請家長補確認來跳過回報或時間設定。

這會取代目前「孩子建立後可以先開始、等待家長確認點數」的寬鬆行為，避免狀態與完成規則互相矛盾。

## 11. 家長端任務分配

### 11.1 建立每日冒險

```text
新增每日冒險

任務名稱
[ 刷牙                              ]

任務說明
[ 記得刷滿兩分鐘                    ]

安排給
[✓ 小宇]  [ 小美 ]
```

### 11.3 編輯每日排程

修改已經開始的每日排程時必須選擇：

```text
只修改今天尚未完成的任務
從明天開始修改
修改今天與未來
```

禁止：

- 修改過去 occurrence。
- 修改已經 `pending` 或 `completed` 的 occurrence。
- 靜默改變已送出任務的點數。
- 刪除排程時連帶刪除歷史任務。

停用排程只影響尚未產生的未來日期。

## 13. 邏輯衝突與最終決策

| 衝突／漏洞 | 最終決策 |
|---|---|
| 左側打勾是否等於已發點 | 否。打勾代表孩子已送出；點數仍等家長核准。 |
| `pending` 是否計入 1/5 | 是，讓孩子獲得立即完成感。 |
| 家長退回後是否仍打勾 | 否，改為 `!`，分子減一。 |
| 每日冒險是否需要心得 | 不需要，也不顯示心得欄位。 |
| 一般冒險能否不回報 | 不能，至少選擇一個簡單回報。 |
| 孩子能否把任務設成每日以跳過心得 | 不能，只有家長可以建立每日排程。 |
| 孩子自建任務能否家長確認前完成 | 不能，只能查看等待確認狀態。 |
| 倒數結束是否自動完成 | 不能，只解鎖完成按鈕。 |
| 本地 timer 是否能證明完成 | 不能；強制計時必須有伺服器 session。 |
| 卡片收合是否暫停 timer | 不會。收合只是顯示狀態。 |
| App 進背景是否繼續 timer | 依伺服器時間計算；不是依畫面 interval。 |
| 每日任務跨日如何重置 | 不重設同一筆；每天建立獨立 occurrence。 |
| 昨天未完成是否帶到今天 | 每日冒險不帶入；一般冒險保留。 |
| 完成任務是否可以重複點擊 | 不可；前端鎖定，後端 idempotent。 |
| 家長是否可能重複發點 | 不可；ledger 對 task approval 必須唯一。 |
| 離線完成如何處理 | 可先顯示本地待同步，但不得發點；同步失敗需回復並提示。 |
| 任務在展開時被家長刪除 | 即時移除；若詳情已開啟則關閉並提示任務已不存在。 |
| 任務在孩子操作時被家長改時間 | 提交時以伺服器最新資料驗證，不能沿用舊畫面。 |
| 兩張卡能否同時展開 | 不能，採單一展開 accordion。 |
| 完成任務是否自動收合卡片 | 不會，保留展開位置並更新勾選。 |
| 一般冒險完成後何時消失 | 留在目前 group，直到家長封存。 |
| 一般冒險改名是否改到歷史 | 只改 group title，不改任務與歷史。 |

## 14. 離線、同步與即時更新

- 冒險卡讀取最後成功同步資料。
- 離線時：
  - 可以瀏覽任務。
  - 可以建立一筆本地待同步完成操作。
  - 不可以顯示已獲得新點數。
  - 左側勾選需有全域「等待同步」狀態說明。
- 重新連線後：
  - 以原 task id 與 idempotency key 提交。
  - 後端重新驗證時間、狀態、timer 與權限。
  - 成功後保留勾選。
  - 失敗後撤回勾選並顯示具體原因。
- Realtime 更新：
  - 不改變卡片展開狀態。
  - 不重播整張卡的進場動畫。
  - 只對新增／變更的任務列做短暫淡入或狀態轉換。

## 17. 資料庫與 RPC 工作

新增 migration，不修改既有 migration。

至少需要：

```text
create/update/archive adventure group
create/update/disable daily schedule
ensure daily occurrences for date
start/pause/resume timer session
submit adventure completion
review adventure completion
```

完成 RPC 不應再固定要求 `reflection text`，而是依 task 的 `completion_report_mode` 驗證。

建議單一完成入口：

```text
submit_adventure_completion(
  target_task_id,
  idempotency_key,
  quick_report,
  reflection,
  mood,
  difficulty
)
```

後端自行讀取 task：

- adventure type
- report mode
- execution window
- timer requirement
- review gate
- current status

前端不得傳入「這是每日冒險，所以不用心得」作為可信判斷。

## 18. 測試需求

### 18.1 純邏輯測試

- 每日／一般冒險正確分組。
- `pending` 與 `completed` 計入分子。
- `revision_requested` 不計入分子。
- 過去每日 occurrence 不出現在今天。
- 一般冒險跨日仍顯示。
- 改 group title 不影響任務。
- 兩張卡只能有一張展開。

### 18.2 完成規則測試

- 每日冒險可無心得提交。
- 每日冒險傳入空心得不會被當成錯誤。
- 一般冒險缺少 quick report 被拒絕。
- reflection 模式空白文字被拒絕。
- proposed 任務不能完成。
- 時間未到、已截止都不能完成。
- review gate 阻擋時不能完成其他任務。
- 強制 timer 未達時間不能完成。
- 修改裝置時間不能提前完成 server timer。
- 同一 idempotency key 不會建立兩次提交。

### 18.3 點數與安全測試

- 孩子提交不立即加點。
- 家長核准才發點。
- 重複核准不重複入帳。
- 跨家庭家長不能審核。
- 其他孩子不能提交。
- 孩子不能修改 adventure type、report mode、points。
- 每日 occurrence unique constraint 有效。

### 18.4 UI 與動畫測試

- 初始兩張卡都收合。
- 點擊每日卡淡入展開。
- 再點一次淡出收合。
- 打開一般卡會收起每日卡。
- 快速交替點擊不會留下透明但可點擊的內容。
- 任務詳情返回後保留原卡展開。
- 完成成功後同一列立即打勾。
- 完成失敗後勾選 rollback。
- reduced motion 下功能完整。
- 鍵盤焦點不會進入已收合內容。

### 18.5 行事曆測試

- 台北日期與星期正確。
- 月界線與跨年正確。
- 停用排程不刪除歷史。
- 修改未來排程不修改過去 occurrence。
- 多裝置同時補產生 occurrence 不重複。
- 每日任務在午夜後顯示新 occurrence。
